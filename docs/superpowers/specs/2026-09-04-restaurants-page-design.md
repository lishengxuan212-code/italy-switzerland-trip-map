# 独立餐厅清单网页设计

## 目标

将现有的《意大利瑞士行程_餐厅筛选清单.xlsx》转为独立的静态网页 `restaurants.html`，供 8–12 人团队在手机上按日期浏览、比较并打开餐厅导航、菜单和官网。

该页面暂不接入 `index.html` 的 Leaflet 行程地图；待用户确认餐厅页体验后再讨论整合。

## 已确认的输入与边界

- 以日期为首要浏览维度，不以城市为首要维度。
- 共有 41 个唯一景点/酒店锚点，每个锚点固定保留 3 家候选，共 123 条关联。
- 9/9–9/11 晚餐在民宿做饭；页面不得把这些日期的餐厅呈现为晚餐建议。
- 团队规模为 8–12 人。正餐店不能默认标注为“无需预约”；预约提示沿用清单中的分级。
- 餐厅距离是坐标直线估算；页面必须明确这是估算，并用 Google Maps 导航链接提供实时路线。
- 菜单链接存在不同核验状态：可访问、仅官网可访问、未核通。页面必须如实展示，不能把未核通链接包装为“已确认菜单”。
- 餐标为规划预算，采用清单已写入的 EUR/CNY 和 CHF/CNY 估算，不含酒；意大利需提示可能另有 coperto。

## 页面信息架构

### 首屏与日期导航

- 顶部固定但轻量：品牌名“意大利・瑞士餐厅清单”、日期范围、当前日期说明。
- 横向可滑动的日期导航：9/4 至 9/12；默认展示 9/4。
- 选中日期后只显示当天的锚点和候选餐厅，减少团队在手机上的信息噪声。
- 当日若有民宿做饭规则，以醒目但不打断阅读的提示条展示。

### 当天锚点

- 按实际行程顺序渲染景点与酒店锚点。
- 每个锚点显示类型、名称、适用餐次和候选数量。
- 默认展开第一个锚点，其余折叠；点击可展开/收起，不依赖 hover。

### 餐厅候选

每个锚点中的 3 家候选按 A、B、C 排序，保留如下内容：

- 餐厅中文名与英文/当地名
- “A 优先讨论 / B 稳妥备选 / C 团队备选”
- 直线估算距离和到达提示
- 预约等级与 8–12 人分桌/预订建议
- 人均当地币与人民币规划餐标
- 推荐理由、爽口菜、菜单核验状态
- 手机端操作：Google Maps 导航、菜单、官网

候选不是“唯一最值得去”的排名。A/B/C 只用于引导团队讨论，不能隐藏 B/C。

### 餐厅图片预览

- 每个日期的内容区顶部增加一个横向滑动的“今日餐厅预览”，展示当天 2–3 家 A 优先候选的真实餐厅或菜品图片。
- 图片只使用餐厅官网或官方社媒公开发布的第一方图片链接；图片下方标明“图片来自餐厅官网”，点击图片打开对应官网。
- 图片采用懒加载，不下载或重新托管原图；图片加载失败时显示餐厅名称和“查看官网图片”的替代内容。
- 不为 123 个条目全部加载图片。此限制是为了控制手机流量、避免页面因第三方图片失效而失真，也避免把无来源图片误作餐厅实拍。

### 辅助筛选与说明

- 提供“全部 / 可直接到店 / 建议预订 / 团队必须预订”的预约筛选。
- 筛选只改变可见条目，不修改源数据，也不重排 A/B/C。
- 页面底部展示距离、餐标、汇率和链接状态的解释。

## 视觉与交互

### 视觉主张

旅行手册感的移动决策界面：暖白纸张底、深海军蓝文字、托斯卡纳番茄红作为预约风险色，克制使用圆角与阴影，避免仪表盘式卡片堆叠。

### 内容层次

1. 日期与当天规则。
2. 景点/酒店锚点。
3. 3 个可比较的餐厅候选。
4. 距离和信息口径说明。

### 动效

- 日期切换：轻量淡入与横向位移，避免页面跳动。
- 锚点展开：高度与透明度过渡，保留键盘/屏幕阅读器语义。
- 餐厅操作按钮：触摸反馈和清晰的按压状态。
- 今日餐厅预览：横向拖动和轻量进入过渡；不自动轮播，避免干扰团队讨论。
- 尊重 `prefers-reduced-motion`，关闭非必要动效。

## 技术与数据流

- 产物：纯静态 `restaurants.html`，可由 GitHub Pages 直接托管；不引入构建步骤或后端。
- 数据：把经核验的 123 条清单整理为页面内 `RESTAURANT_DATA` 常量；不在浏览器运行时读取 `.xlsx`，避免手机端解析性能和跨域问题。
- 外链：所有第三方链接使用 `target="_blank"` 和 `rel="noopener"`。
- 餐厅图片只引用第一方公开页面，不将图片文件纳入仓库；图源不可用时优先显示替代内容而非第三方图库图片。
- HTML 采用语义化按钮与区域标签；日期栏、筛选器和折叠区支持键盘访问。
- CSS 使用原生响应式布局；手机为主，桌面以双栏阅读增强，不改变内容顺序。

## 异常与事实边界

- 数据中没有实时桌位或实时营业状态，因此网页不能显示“可订”或“正在营业”。
- 对“官网/菜单链接本次未核通”的条目，按钮文案应显示“出发前核对”，同时仍可提供官网/地图搜索链接。
- 乡间、First 缆车沿线和威尼斯等地点的距离说明必须保留其路线限制，不作步行可达承诺。
- 页面只显示现有清单中的餐厅，不自动新增或删除餐厅。

## 验收标准

- 手机宽度 375px 下：日期栏可横向滑动、触控目标不小于 44px、核心信息无需横向滚动。
- 每个日期只显示对应当天的锚点；9/9–9/11 不出现“晚餐推荐”表达。
- 41 个锚点与 123 条候选均可被渲染和筛选到。
- 每条候选均具有距离、预约、餐标、链接状态和至少一个可操作外链。
- 每个有可用第一方图片的日期展示 2–3 张懒加载预览；失败时展示可操作的官网替代内容。
- Google Maps、菜单和官网链接不在当前页面打开。
- `prefers-reduced-motion` 时不播放展开/切换动画。
- 不修改 `index.html` 的现有地图功能。
